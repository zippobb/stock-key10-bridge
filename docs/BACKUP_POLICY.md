# 股票选股系统 GitHub 备份规则

## 目标

本仓库作为 `/opt/stock-automation/scanner` 的长期版本与历史数据备份仓库。仓库保持私有。

## 保存范围

以下内容全部保存：

- 选股系统源代码、内部模块和工具脚本
- 不含密钥的配置文件与配置样例
- Python依赖清单、系统服务、定时任务和部署说明
- 候选图模板、字体说明和生成脚本
- 每次版本更新记录、验证记录、部署记录和回滚说明
- 股票池快照、池内候选、池外推荐、审计结果和最终PNG
- 行情原始数据、历史日线、指标表、板块指标及其快照
- 数据清单、文件大小、SHA256校验值和数据截止时间

## 必须排除

不得提交任何敏感配置或凭证，包括：

- `.env`及其变体
- Tushare、Wind、GitHub等API密钥或令牌
- SSH私钥、证书、Cookie、密码和鉴权头
- 包含上述敏感值的日志、命令历史或导出文件

备份前必须执行敏感信息预检。预检失败时停止提交和推送。

## 仓库结构

```text
src/                 生产源代码
config/              非敏感配置与样例
deploy/              systemd、timer、cron及部署文件
templates/           PNG模板与制图资源
docs/versions/       每个版本的完整变更记录
snapshots/pools/     正式股票池快照
results/YYYY/MM/DD/  每日池内、池外、审计和最终图片
data/market/         行情及衍生指标数据
manifests/           文件清单与SHA256校验
scripts/             备份、恢复和校验脚本
```

## 大文件策略

行情CSV、压缩CSV、Parquet、Excel和PNG由Git LFS跟踪。大于100MB的单文件在备份前按交易年月或交易日拆分或压缩分区，确保单个对象可稳定上传和恢复；不得因为体积大而省略行情数据。

## 版本策略

- `main`：当前已部署且验证通过的生产版本及完整历史。
- 每次更新先在独立分支提交，通过核对后再合并。
- 部署版本使用标签：`v2.0`、`v2.1`等。
- 版本记录至少包含：版本号、修改时间、修改原因、修改内容、指标/阈值/权重变化、部署时间。
- 标签对应的提交必须能够恢复该版本代码、配置、定时任务和制图模板。
- 不改写既有版本标签，不强制推送覆盖历史。

## 服务器保留

新版本部署并验证成功后：

- 服务器保留当前生产版本；
- 服务器另保留上一旧版本的完整可回滚备份；
- 服务器继续保留历史结果和运行所需数据；
- 更早的程序版本长期保存在本GitHub仓库。

## 每日备份

服务器每日选股链路完成后，保存当日股票池、行情、指标、候选、审计结果、最终PNG和校验清单。若GitHub推送失败，不删除服务器本地文件，并记录失败等待补传。

## 恢复要求

恢复时必须先校验提交或版本标签，再核对清单和SHA256；敏感配置从服务器受控位置重新注入，不从GitHub恢复。
